# 每日记账 —— 项目文档（CLAUDE.md）

> 本文档是「每日记账」项目的总纲：记录产品定位、功能需求、用户决策与技术方案。
> 每次开发前先读本文档，开发后同步更新「九、开发进度记录」。

## 一、项目概述

- **应用名称**：每日记账
- **平台**：Windows 桌面应用
- **使用方式**：单机本地使用，无需注册登录，不联网
- **核心功能**：记录用户每一笔收入和支出，分类为两级结构（一级大科目 → 二级子类科目），并支持月度统计、预算提醒、搜索筛选
- **核心目标**：记一笔账不超过 10 秒；随时看清钱花在了哪里、每月结余多少
- **目标用户**：非技术人员。界面与操作必须直观简单，全部使用中文日常用语，不用专业术语
- **代码位置**：项目代码与本文档均位于 `记账app/` 目录下（git 仓库根为工作区 `d:\vscode\Vscode project`）

## 二、与用户的沟通规则（铁律，全程必须遵守）

用户是普通使用者、不懂技术。开发全过程中必须遵守以下规则：

1. **技术决策用大白话解释**：任何技术选择（用什么工具做软件、数据存在哪里、用什么格式保存等），都要用生活化语言讲清楚「它是什么、能干什么、对用户有什么影响」，禁止堆砌专业术语。
2. **必须先列优劣势对比**：每提出一个技术方案，至少要用「好处 / 坏处 / 对您的影响」的形式给出通俗对比，让用户能听懂、能比较。
3. **由用户拍板**：所有技术决策必须经用户明确同意后才执行，不得默认替用户做决定。包括但不限于「这个方案更专业所以直接用」「这个很简单不用问」这类情况，一律先说明、再等用户确认。
4. **够用就好，不主动加码**：优先选择最简单的方案；一个功能有多种做法时，先说明区别，由用户选择。
5. **主动讲清风险**：涉及数据会不会丢、换电脑能不能迁移、软件坏了怎么恢复等数据安全问题，必须提前向用户解释清楚，并提供备份手段。
6. **用具体例子沟通**：讲解任何功能或方案时，尽量用「比如您记一笔 28 块 5 的外卖支出……」这样的实际例子，不要抽象描述。
7. **完成后说明并请试用**：每完成一个功能，用通俗语言向用户说明「做了什么、怎么用、在哪里看」，并请用户实际试用确认。

## 六、账单数据结构

一条账单记录包含以下字段：

| 字段名 | 说明 | 示例 |
| --- | --- | --- |
| id | 账单唯一编号，自动生成 | 1001 |
| type | 收支类型：`expense`（支出）或 `income`（收入） | expense |
| amount | 金额，以「分」为单位的整数存储（28.50 元存为 2850），避免小数计算误差 | 2850 |
| category | 一级大科目 | 餐饮 |
| subcategory | 二级子类科目 | 外卖 |
| date | 账目实际发生日期 | 2026-08-23 |
| note | 备注，可选，最多 100 字 | 午饭外卖 |
| createdAt | 记录创建时间，自动记录 | 2026-08-23 12:30:00 |
| updatedAt | 最后修改时间，自动更新 | 2026-08-23 12:31:00 |

补充规则：

- 记账日期默认当天，但允许修改（补记昨天的账）。
- 金额只允许正数，收入与支出靠 `type` 字段区分。
- 界面显示金额时换算成「元」（2850 → 28.50），存储始终用「分」。
- 分类在账单中直接存名称（v1 简化方案）；若用户在分类管理中改名，历史账单是否同步更新，开发时向用户说明后确认。

## 七、技术方案记录

### 7.1 四方案通俗对比（2026-08-23 向用户提供，均已用大白话解释）

| 方案 | 是什么（大白话） | 好处 | 坏处 / 代价 | 对您的影响 |
| --- | --- | --- | --- | --- |
| A. Electron 桌面应用 **（已选定 ✅）** | 把网页技术装进软件壳里，变成像微信一样双击图标打开的独立窗口软件。VS Code、钉钉都是同款做法。 | 数据存在软件自己的数据库文件里，最安全稳妥；界面可以做得很漂亮；技术成熟可靠。 | 安装包较大（约 100MB）；开发时电脑需先装 Node.js（由开发助手帮装，一步完成，不影响日常使用）。 | 安装一次后双击图标就能用；数据不怕浏览器清理，最省心。 |
| B. Python 桌面应用 | 用 Python 语言写的传统桌面软件。 | 电脑已装好 Python，无需额外环境，开发最顺畅。 | 界面偏「传统软件」风格，美观度一般；打包成 exe 后体积大、启动稍慢。 | 能用，但外观与流畅度不如 A。 |
| C. 网页应用（免安装） | 浏览器打开即用的网页，双击文件就能用。 | 零安装、最轻量、界面最好看；以后想放到手机上用也方便。 | 数据保存在浏览器里，清理浏览器数据会全部丢失；不是独立软件窗口。 | 最方便但数据最不安全，必须靠导出备份兜底。 |
| D. Tauri 桌面应用 | 和 A 一样是独立窗口软件，但更轻巧。 | 体积小 10 倍（约 10MB）、更省内存、启动更快。 | 电脑需要装几 GB 的 Rust 开发环境，配置复杂，后续改动排查问题成本高。 | 成品体验最好，但开发风险高、周期长。 |

**最终决定（用户拍板）**：2026-08-23，用户选定 **A. Electron 桌面应用**。

## 八、开发约定

1. 界面与文案全部使用中文日常用语，不用专业术语（对应用户沟通规则）。
2. 每次改动后同步更新「九、开发进度记录」。
3. 重大功能完成后，用通俗语言向用户说明「做了什么、怎么用、在哪里看」，并请用户试用确认。
4. 项目代码统一放在 `记账app/` 目录下；目录结构与技术细节由开发助手按 Electron 标准实践组织，无需用户关心。
5. 涉及数据安全、技术选型等决策时，先解释对比、再等用户拍板（严格遵守「二、与用户的沟通规则」）。
6. **本机开发环境怪癖**：VS Code 注入的环境变量 `ELECTRON_RUN_AS_NODE=1` 会让 Electron 以 Node 模式启动而崩溃。在本机终端启动应用前必须先执行 `unset ELECTRON_RUN_AS_NODE`（对用户双击安装版无影响）。
7. Node.js 位于 `D:\Node`（免安装版，用户 2026-08-23 指定位置）。若终端找不到 node/npm，先执行 `export PATH="/d/Node:$PATH"`。
8. **版本管理（git）**：仓库位于工作区根目录 `d:\vscode\Vscode project`（含本文档与全部代码），主分支 `main`。每完成一个功能里程碑就提交一次（`git add -A && git commit`），提交信息用中文简述「做了什么」；node_modules/out/dist 等大目录已在 .gitignore 中排除，不纳入管理。
